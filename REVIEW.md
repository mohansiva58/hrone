# REVIEW.md

List of defects found in the starter `app/main.py` (helpers and endpoints):

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `list_employees` | Pagination skip calculated as `skip = page * page_size`, skipping the first page completely when `page=1`. | Querying `GET /employees?page=1` returned items from page 2 instead of page 1. | Fixed calculation to `skip = (page - 1) * page_size`. |
| 2 | `list_employees` | `total` count used `count_documents({})` ignoring the `department` query filter. | `GET /employees?department=Engineering` returned `total` of all employees across all departments instead of filtered count. | Updated to `count_documents(q)`. |
| 3 | `list_employees` | Missing sort parameter in database query. | Results were returned in non-deterministic natural insertion order instead of `emp_code` ascending. | Added `.sort("emp_code", 1)` to the PyMongo find query. |
| 4 | `punch_in` | Unhandled `None` lookup when employee does not exist. `emp["shift_start"]` raises `TypeError`. | Calling `POST /attendance/punch-in` with non-existent `emp_code` resulted in HTTP 500 Internal Server Error. | Added check `if not emp: raise HTTPException(404, "Employee not found")`. |
| 5 | `punch_in` | Race condition: used application-level check-then-insert (`find_one` followed by `insert_one`). | Concurrent punch-in requests for the same employee and date both succeeded, inserting duplicate daily logs. | Created a compound unique index on `(emp_code, date)` and caught `DuplicateKeyError` to return HTTP 409 Conflict. |
| 6 | `punch_in` & `list_attendance` | Response included MongoDB `_id` cast to string as `id`. | Violates OpenAPI contract schema which forbids internal `_id`. | Stripped `_id` and formatted response strictly matching `AttendanceRecord` schema. |
| 7 | `punch_in` | R1 overnight shift date logic was missing (`ts.date().isoformat()` was used blindly). | An overnight shift punch-in at 01:30 IST was assigned to the current calendar date instead of the shift start date of the previous day. | Added `get_attendance_date` helper enforcing R1 overnight shift rules (`shift_end <= shift_start`). |
| 8 | `list_attendance` | Loaded all documents into Python memory (`list(db.attendance_logs.find(q))`) and sorted in Python. | High latency and memory exhaustion on large collections (~100k documents). | Moved sorting, `.skip()`, and `.limit()` directly into the MongoDB query. |
| 9 | `list_attendance` | Sorted by `date` descending only. | `GET /attendance` failed to order items with identical dates by `emp_code` ascending. | Added composite sort `.sort([("date", -1), ("emp_code", 1)])`. |
| 10 | `compute_late_minutes` | Used naive datetime replacement without timezone handling, and simple float division. | The R2 boundary for a 09:30 IST shift is 09:40:00 → 0 and 09:40:01 → 10; late minutes count whole minutes from shift start after the strict grace-period comparison. | Converted timestamps to IST (`UTC+05:30`), computed `diff_seconds = (punch_in_ist - shift_start_ist).total_seconds()`, and applied the `> 600` grace period check before integer floor division. |
| 11 | `compute_work_hours` | Used Python's built-in `round()` rather than decimal half-up rounding required by R4. | `round(2.675, 2)` evaluates to `2.67` because the input is a binary float; decimal half-up rounding of 2.675 is `2.68`. | Replaced `round()` with `Decimal.quantize` using `ROUND_HALF_UP`. |
| 12 | `compute_overtime` | Overtime cutoff (>= 30 mins) was ignored, and overnight shift end dates were miscalculated. | 15 minutes of overtime returned `15` instead of `0` (R3 requirement). | Implemented 30-minute minimum threshold check and correct overnight shift end date logic. |
| 13 | `create_employee` | Relied on application-level duplicate `emp_code` checks, which are not race-safe, and did not enforce the endpoint contract that shift boundaries differ. | Concurrent creates with the same employee code could both pass an application pre-check; creating an employee with equal shift boundaries should return 422. | Added a unique index on `emp_code` and handle `DuplicateKeyError` as 409; employee request validation rejects equal boundaries while the overnight helper still classifies existing equal-time records as overnight. |
| 14 | Startup Indexes | No database indexes were created at application startup. | All queries and explain calls resulted in COLLSCAN. | Implemented FastAPI lifespan hook creating required indexes on `employees` and `attendance_logs` idempotently. |
| 15 | `regularize_attendance` | Optimistic-lock filter required `history: []` exactly, so legacy documents that were stored without a `history` field could never be regularized (always 409). | Any attendance record created before the `history` array was introduced would return 409 on every regularization attempt. | Changed filter to `$or: [{ history: { $exists: false } }, { history: [] }]` when the in-memory document has no history, so the update matches both the old schema and the new empty-array schema. |
| 16 | `explain_endpoint` | Used simplified stub pipelines (`[$match]` only) instead of the real aggregation pipelines. | Explain results did not reflect the actual query plan; `$group`, `$lookup`, and `$setWindowFields` stages were absent. | Extracted pipeline builders (`_build_employee_monthly_pipeline`, `_build_department_summary_pipeline`, `_build_late_leaderboard_pipeline`, `_build_department_trend_pipeline`) shared by both real endpoints and the explain endpoint. |
| 17 | `list_attendance`, `regularize_attendance`, `department_trend` | Date parameters validated only by regex `\d{4}-\d{2}-\d{2}`, accepting impossible dates such as `2026-02-30`. | Passing an impossible date like `2026-02-30` as `date_from` raised a 500 internal error inside MongoDB or Python instead of a clean 422. | Added `validate_date_str(s, field_name)` helper using `datetime.date.fromisoformat`, raising `HTTPException(422)` on `ValueError`. |
| 18 | `list_attendance` | `status` query parameter was not validated against the allowed enum values before being forwarded to MongoDB. | Passing `status=WORKING` silently produced an empty result instead of a 422 validation error. | Added `VALID_ALL_STATUSES` frozenset and a guard that raises `HTTPException(422)` for unrecognised values. |
| 19 | `PunchInIn`, `PunchOutIn`, `RegularizeIn` | Explicit nulls for non-nullable inputs must be rejected, while the four known read-only derived fields (`work_hours`, `late_minutes`, `overtime_minutes`, `half_day`) must be ignored rather than treated as unknown input. | Explicit `punched_at: null` must return 422; sending a valid timestamp plus a forged derived value must still succeed with server-computed output; unrelated unknown fields must remain 422. | Before validation, strip only those four derived fields. Keep explicit-null checks and `extra="forbid"` for all unrelated fields. |
| 20 | `punch_out` | Punch-out conditional update checked only `punch_out: None`, allowing punch-out to persist derived fields calculated from a stale `punch_in` if a regularization occurred between reading and writing. | Interleaved regularization changing `punch_in` or `status` during punch-out caused stale `work_hours` or punch times to be persisted without conflict detection. | Strengthened CAS filter in `find_one_and_update` to verify `_id`, `punch_out: None`, `punch_in: doc["punch_in"]`, and `status: doc["status"]`, returning HTTP 409 Conflict on mismatch. |
| 21 | FastAPI route decorators | Generated Swagger/OpenAPI documented success responses with empty schemas and omitted contract-defined 404/409/422/503 responses on several routes. | Calling `app.openapi()` showed path/method coverage but incomplete response schemas and missing error status codes, despite runtime handlers returning those errors. | Added response models and route `responses` metadata in `app/main.py`, preserving existing runtime payloads. |
| 22 | `regularize_attendance` audit history | Legacy BSON datetimes with fractional seconds were normalized in current punch fields, but the raw fractional values could be written into `history.changes`. | A legacy record with `punch_in`/`punch_out` microseconds, then a PATCH changing status, left microseconds in persisted audit history. | Truncated prior punch timestamps before comparing and storing `history.changes`, and added regression assertions for persisted and returned history precision. |

### Things examined and verified as NOT defects:
- `IST` timezone definition (`timezone(timedelta(hours=5, minutes=30))`): Verified correct for converting UTC BSON dates to IST calendar dates.
- Pydantic models reject explicit null for non-nullable inputs, ignore known derived fields, and reject unrelated extras; FastAPI returns HTTP 422 for invalid requests.
- `attendance_pct` precision: Computed as `(present_days / working_days) × 100` — this is a percentage and correctly uses 2 decimal places (ROUND_HALF_UP per R8). `attendance_rate` and `moving_avg_7d` in the trend endpoint are rates (0–1) and correctly use 4 decimal places.
